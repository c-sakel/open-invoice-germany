## 1. Fachliche Klärung
- GoBD: Alles in Phase 11 ist Darstellung und Bedienung. Beleginhalt, Snapshots, Hash-Chain, Nummernvergabe, E-Rechnung bleiben unangetastet. Die Layout-Wahl ist eine Druckoption im Sinne von Phase 7: sie wird je Beleg im bestehenden `printOptionsJson`-Override abgelegt und beim Festschreiben eingefroren (bestehender Guard). Ein später geändertes Organisations-Layout verändert festgeschriebene Belege daher nicht; Belege ohne Override (Altbestand) nutzen das Organisations-Layout, was dem bisherigen Verhalten bei Branding-Änderungen entspricht (Phase-7-Ruling, LIMITATIONEN).
- E-Rechnung (§52): XRechnung/ZUGFeRD-XML ist layoutunabhängig. Der ZUGFeRD-PDF-Teil wird mit dem gewählten Layout gerendert; Validatoren bleiben CI-Gate.
- Interne Notizen (§48) erscheinen weiterhin in keinem Layout.
- Abgrenzung (§60): keine Tags, Kostenstellen, Zeiterfassung, Bank, Steuern, Belege-Erfassung; kein Premium-/Baukasten-Layout; kein Mehrbenutzer.

## 4. Tests
- Layout-Register: jedes Layout rendert Rechnung, Gutschrift, Angebot, Lieferschein, Mahnung mit Musterdaten (2 Seiten, 15 Positionen, Langtext, Rabatt, Skonto, GiroCode) ohne Fehler; `pdf-parse`-Text enthält Belegnummer, Kundenname, Netto/USt./Brutto, Fußzeilendaten (IBAN, USt-IdNr.), „1/2" bzw. „Seite 1 von 2"; Tabellenkopf auf Seite 2 (Text „Beschreibung" zweimal). Interne Notizen nie im Text (Negativtest je Layout).
- `effectiveLayoutId`: Override > Typ-Map > Organisation > `standard`; unbekannte Id ⇒ `standard`; Einfrieren beim Festschreiben setzt `layoutId` in `printOptionsJson`, nachträgliche Organisationsänderung lässt das PDF-Layout des festgeschriebenen Belegs unverändert (Text-Vergleich zweier Renderings).
- AUTO-Fußzeile: vier Spalten aus Organisationsdaten, fehlende Felder lassen Zeilen entfallen, CUSTOM überstimmt.
- Zod: Branding-Update mit ungültiger `layoutId` ⇒ 400; `layoutByType` mit unbekanntem Typ ⇒ 400; API v1 und MCP dieselben Fehler.
- Suche: org-gescoped (fremde Org liefert nichts), min. 2 Zeichen, Gruppierung, Limit.
- Entwurfs-Vorschau: `POST /api/pdf/preview` validiert wie Speichern, schreibt nichts (DB-Zählung vorher/nachher), liefert `application/pdf`.
- Editor/Detail: keine Komponententests (kein RTL im Projekt); stattdessen `npm run build`, Typecheck, Lint, und je Teilphase ein Playwright-Smoke über das `webapp-testing`-Skill (Rechnung anlegen → Position per Produktsuche → Vorschau → Speichern → Festschreiben → Detailseite zeigt PDF und Statuskarte) als Abschluss-Review-Schritt, nicht als CI-Gate.
- Bestehende 1672 Tests, `validate:erechnung`, Postgres-Migrationsskript, `api:check` bleiben grün; `TZ=UTC npm test`.
