# Phase 10 — REST-API (OpenAPI/Swagger, API-Keys) und Webhooks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Öffentliche, versionierte REST-API `/api/v1` mit API-Keys, einheitlichem Antwort-/Fehlerformat, Paginierung/Filter/Embed, aus Zod generierter OpenAPI-3.1-Spezifikation mit Swagger-UI und CI-Drift-Check; Webhooks (Outbox in derselben Transaktion, HMAC-Signatur, Retry, Zustellprotokoll, Test/Replay) über den Phase-6-Scheduler.
**Architecture:** `src/api/` (auth, errors, response, openapi, rate-limit, idempotency), Routen `src/app/api/v1/<Resource>/...` als dünne Wrapper über die vorhandenen Domain-Funktionen; `src/domain/api-key/`, `src/domain/webhook/` (endpoints, emit=Outbox, deliver, sign); Swagger-UI aus `swagger-ui-dist` (node_modules, kein CDN); Spec-Datei `openapi/openapi.json` + `npm run api:check`.
**Tech Stack:** Next.js 16, Prisma 6, Zod 4, `@asteasolutions/zod-to-openapi` (Zod-4-Kompatibilität in Task 1 prüfen, sonst `zod-openapi`), `swagger-ui-dist`; Rate-Limit-Modul aus Phase 3b; Scheduler aus Phase 6.
**Spec:** docs/superpowers/specs/2026-09-03-phase-10-api-design.md (specs).

## Global Constraints
- Kein Bypass: jede v1-Route ruft exakt die Domain-Funktion, die UI/MCP nutzen; Zod-Schemas aus `src/schemas`; GoBD-Fehler → 409; Zod → 400 `{error:{code:"VALIDATION",details:{issues}}}`; 401/403/404/429/500 wie Spec.
- API-Keys: `oig_` + 32 Byte base64url, nur SHA-256-Hash gespeichert, Prefix (8 Zeichen) zur Anzeige, Scopes read/write/send/admin, expiresAt/revokedAt, lastUsedAt; `/api/v1/*` akzeptiert NUR Bearer (kein Cookie); Proxy (`src/proxy.ts`) lässt `/api/v1` ohne Session durch, Auth in `src/api/auth.ts`.
- Rate-Limit 600/min je Key (In-Memory-Modul), Header `X-RateLimit-Remaining`, 429 + `Retry-After`.
- Idempotency-Key (Header) für POST-Aktionen: Modell `ApiIdempotency {orgId, key, requestHash, responseJson, createdAt}`, 24 h, Wiederholung liefert dieselbe Antwort; abweichender requestHash → 409.
- Audit: schreibende Aktionen laufen mit `actor = "api:<keyName>"` in ChangeLog/ActivityLog.
- Antwortformat: `{data}` bzw. `{data, total, limit, offset}`; Geld Integer-Cent; Daten ISO 8601; `embed=customer,lines`.
- OpenAPI 3.1 aus Zod generiert; `openapi/openapi.json` im Repo; `npm run api:check` (Generat == Datei) als CI-Gate; Swagger-UI `/api/docs` (Session ODER Key); deutsche Beschreibungen und Beispiele.
- Webhooks: Outbox-Zeile in derselben Tx wie ChangeLog (`emitEvent(tx, …)`); Zustellung nur über Scheduler-Job `webhooks` (seriell, Lock); Signatur `X-OIG-Signature: t=<ts>,v1=<hmac_sha256(secret, ts + "." + body)>`; Retry 5× Backoff 1/5/30/120/600 min → DEAD; Secret AES-GCM verschlüsselt (Phase-3b-Modul), nie im UI nach Erzeugung; nur https, SSRF-Schutz (DNS-Auflösung, private Netze verboten); Payload ohne internalNotes.
- Migrationen SQLite+Postgres identisch; Tabellen +4 (ApiKey, ApiIdempotency, WebhookEndpoint, WebhookDelivery).
- Testjahre 2073 api-auth, 2074 api-resources, 2075 api-actions, 2076 openapi, 2077 webhooks (vorher prüfen). Prüfkette im Vordergrund; letzter Task Postgres-Skript.
