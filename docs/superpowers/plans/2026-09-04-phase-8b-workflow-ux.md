# Phase 8b — Workflow und UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dynamischer Rechnungsstatus, Listenfilter/Suche, Zeilen-Schnellaktionen, Zahlungsdialog-Ergänzungen, Wiederkehrend-Erweiterungen, ActivityLog + Timeline, Dashboard, Kundendetailseite, In-App-Benachrichtigungen, gruppierte Navigation und progressive Formulare.

**Architecture:** Reine Statusfunktion und Aktionsmatrix in `src/domain/invoice/status.ts` / `src/domain/document/actions.ts`; Listen-Domain mit Zod-Filter; `ActivityLog` als eigene Tabelle ohne Hash-Kette, Schreiber `logActivity` in bestehenden Domain-Funktionen; Timeline-Merge in `src/domain/timeline/`; Aggregationen in `src/domain/dashboard/` und `src/domain/customer/overview.ts`; Benachrichtigungen mit Scheduler-Job `notifications` (Phase-6-Runner) und Ereignis-Hooks; UI-Komponenten wiederverwendbar (RowActionsMenu, FilterBar, Timeline, NotificationBell).

**Tech Stack:** Next.js 16, Prisma 6, Zod 4, vitest.

**Spec:** docs/superpowers/specs/2026-09-04-phase-8b-workflow-ux-design.md (specs); Ist-Stand phase-8-ist-stand.md.

## Global Constraints
- GoBD: ActivityLog ist KEIN Audit-Ersatz — ChangeLog-Aufrufe bleiben unverändert; ActivityLog-Schreiber laufen in derselben Tx wie das Ereignis, dürfen aber das Ereignis nicht verhindern (kein throw aus logActivity, Fehler nur loggen). Keine Änderung an festgeschriebenen Belegen.
- Status fällig/überfällig wird nie gespeichert; alle Anzeigen/Filter nutzen `effectiveInvoiceStatus`.
- Geld Integer-Cent; Aggregationen über `openAmountCents`/`payableBaseCents` (Phase 5), DB-portabel (SQLite + Postgres; keine DB-spezifischen Funktionen; Aggregation notfalls in JS über `select`-reduzierte Zeilen).
- Zod an jeder Boundary (Filter-Query, Notification-Settings, Payment-Note); Routen/MCP/UI dieselben Domain-Funktionen; org-scoped.
- Migrationen SQLite+Postgres (Schemadateien identisch); Tabellen danach 39 (ActivityLog, Notification, NotificationSettings).
- Bestehende Tests nicht schwächen; Testjahre 2063 status/filter, 2064 payment/recurring, 2065 activity/timeline, 2066 dashboard/customer-overview, 2067 notifications, 2068 routes/mcp (vorher `grep -r "206[3-8]-" test/`).
- Prüfkette im Vordergrund vor jedem Commit-Abschluss: typecheck, lint, test, build, validate:erechnung; letzter Task zusätzlich Postgres-Skript.
