# Phase 7 — Einstellungen, Nummernkreise, Briefpapier, Druckoptionen, GiroCode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Belegeinstellungen (§33) mit Konsum in allen Anlagepfaden, Nummernkreis-UI inkl. Kunden-/Artikelnummern (§34), Briefpapier mit Logo/Farbe/Rändern/Vorschau (§35), Druckoptionen global + je Beleg (§36), EPC-GiroCode auf Rechnungen (§37).

**Architecture:** Settings-Domain unter `src/domain/settings/` (document erweitert, print, branding) und `src/domain/numbering/ranges.ts`; PDF-Renderer werden auf ein `PdfTheme` (Branding + effektive Druckoptionen) umgestellt, Marken/Seitenzahlen/GiroCode als kleine reine Module; Dateien (Logo/Hintergrund) über den Phase-4b-Speicher; UI als vier Settings-Seiten plus Druckoptionen-Panel im Beleg-Editor; MCP-Tools spiegeln die Settings-Funktionen.

**Tech Stack:** Next.js 16, Prisma 6 (SQLite+Postgres), Zod 4, pdfkit (bufferPages), `qrcode` (neu, prod), `pdf-parse` (neu, dev), vitest.

**Spec:** docs/superpowers/specs/2026-09-04-phase-7-settings-pdf-design.md (Branch specs); Ist-Stand phase-7-ist-stand.md (Scratchpad).

## Global Constraints
- GoBD: Beleginhalt unverändert; `printOptionsJson` auf Belegen nur im Entwurf änderbar (Invoice-Guard greift automatisch; Quote/DeliveryNote: Domain prüft Status DRAFT); Nummernkreis-Änderungen → ChangeLog `entity: "SETTINGS", entityId: "NUMBER_RANGE:<docType>"`, action UPDATE, diff alt/neu; Nummern nie zurückdrehen.
- Geld Integer-Cent; EPC-Betrag aus Cent formatiert `EUR123.45` (Punkt, zwei Nachkommastellen).
- Zod an jeder Boundary; Routen/MCP/Formulare nutzen dieselben Domain-Funktionen; Uploads mit Magic-Byte-Prüfung (PNG/JPEG), Größenlimit 2 MB Logo, 5 MB Hintergrund.
- Migrationen SQLite UND Postgres (Schemadateien identisch bis auf provider; Postgres via `prisma migrate diff --script` falls `migrate dev` verweigert). Tabellen danach 35 (BrandingSettings, PrintSettings). Bestandsdaten: DocumentSettings-Zeilen bekommen Defaults; keine destruktiven Änderungen.
- Neue Abhängigkeiten nur `qrcode` (prod) und `pdf-parse` (dev). Keine CDN-/Netzressourcen im PDF.
- Bestehende PDFs/Fixtures/E-Rechnung bleiben gültig (`validate:erechnung` grün); XML unberührt.
- Testjahre: 2054 settings-consumption, 2055 number-ranges, 2056 pdf-theme/giro, 2057 settings-routes, 2058 mcp-settings (vorher `grep -r "205[4-8]-" test/` prüfen).
- Prüfkette vor jedem Commit-Abschluss im Vordergrund: typecheck, lint, test, build, validate:erechnung; Task 5 zusätzlich Postgres-Skript.

**Files:** Create `src/lib/pdf/theme.ts` (`PdfTheme { brand: BrandingSettings-like; options: EffectivePrintOptions; logoBuffer?: Buffer; backgroundBuffer?: Buffer }`, `loadPdfTheme(orgId, overrideJson)` in `src/domain/settings/theme.ts` — liest Dateien über Storage), `src/lib/pdf/marks.ts` (`drawFoldMarks(doc)`: Linien bei 105 mm und 210 mm, 5 mm lang, ab 3 mm vom linken Rand; `drawPunchMark(doc)`: 148,5 mm; `drawPageNumbers(doc, theme)` nach `bufferPages`: „Seite x von y" rechts unten), `src/lib/pdf/epc.ts` (`buildEpcPayload`, Fehlerklasse `EpcError`), `src/lib/pdf/giro.ts` (`renderGiroCode(doc, payload, {x, y, sizeMm})` via `qrcode.toBuffer(payload, {errorCorrectionLevel: "M", margin: 0, width: 300})`), `src/lib/pdf/layout.ts` (mm→pt, Ränder aus Theme, Absenderzeile, Footer-Spalten, Logo rechts oben mit `logoWidthMm`, Hintergrundbild vollflächig zuerst); Modify `src/lib/pdf/invoice-pdf.ts`, `delivery-note-pdf.ts`, `dunning-pdf.ts` (Theme-Parameter statt Konstanten; Spalten nach Optionen: Artikelnummer, Beschreibung, USt-Satz je Position, Positionssummen; Absenderzeile/Footer/Seitenzahlen/Marken/GiroCode nach Optionen; Farbe `primaryColor` für Titel/Linien); PDF-Routen und `src/domain/email/attachments.ts` laden Theme; `package.json` (+ `qrcode`, `@types/qrcode`, dev `pdf-parse`); Tests `test/unit/epc.test.ts`, `test/unit/pdf-marks.test.ts`, `test/integration/pdf-theme.test.ts` (Jahr 2056: PDF-Text via pdf-parse enthält „Seite 1 von 2" bei langer Rechnung; GiroCode-Bild vorhanden → PDF enthält Image-XObject; ohne IBAN kein Code; Gutschrift kein Code; Delivery-note Lieferadresse).
**EPC exakt:** Zeilen mit `\n` getrennt, kein Trailing-Newline: `BCD`,`002`,`1`,`SCT`,`<BIC oder leer>`,`<Name>`,`<IBAN>`,`EUR<amount>`,``,``,`<remittance>`; `amount` = `(cents/100).toFixed(2)`; Beispiel Name „Muster GmbH", IBAN `DE02120300000000202051`, BIC leer, 11900 Cent, Remittance `RE-2056-00001` → `BCD\n002\n1\nSCT\n\nMuster GmbH\nDE02120300000000202051\nEUR119.00\n\n\nRE-2056-00001`. Byte-Länge ≤ 331 sonst `EpcError`; Name > 70 → `EpcError`; amountCents < 1 oder > 99999999999 → `EpcError`; IBAN Leerzeichen entfernen, Großschreibung.
**GiroCode-Platzierung:** im Zahlungsblock rechts, 30 mm, Beschriftung darunter „GiroCode – mit Banking-App scannen"; Betrag = `payableBaseCents − paidAmountCents` zum Renderzeitpunkt; nur Typen INVOICE/PARTIAL/DOWNPAYMENT/FINAL/CORRECTION; nur wenn `options.showGiroCode && org.iban`.
